# Meko Joins the Memory-Layers Study: Datapacks as the Unit of Agent Memory

## Why Care?

Most entries in this study scope memory by user, session, or agent. Meko scopes it by **datapack**: a named workspace holding memories, knowledge files, conversation turns, decision traces and artifacts together, with one dedicated datapack per project for writes and shared ones attached across projects. It also writes down, per repo, which datapacks an agent must search before touching code (`MEKO.md`), the same move as our own "query the Chroma corpus first" rule, enforced from code by its Kode extension.

## What changed

- **Pinned** `yugabyte/meko` at `7bb83da` (2026-11-23, release `meko-v1.20261123.0`), Apache-2.0.
- **Profiled** in `context-v/profiles/Profile__Meko.md`, scored against the study's checklist from the pinned source, with a short section contrasting datapacks (knowledge) with skill packs (instructions).
- **README:** a row in the design-space table and a "Why this is here" entry.

## Worth knowing

- Despite coming from a database company, the local store is SQLite with sqlite-vec and FTS5, not YugabyteDB, capped at 200 MB so a memory search stays near 771 ms.
- The retrieval engine is upstream mem0 with a no-op LLM; extraction runs the user's own `claude -p` on Haiku and drops anything within 0.9 cosine of an existing memory.
- Access roles and the "gotchas" miner exist only in the private Meko Cloud; locally every datapack is owner-only.
