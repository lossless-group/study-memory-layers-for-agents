# The Memory-Layers Profiles Carry the Kit's Metadata Template

## Why Care?

[[2026-11-01_01]] made `memory-layers-for-agents/context-v/` an Open Knowledge Format bundle. This pass brings the same 18 profiles up to the Context Vigilance Kit's frontmatter template, so a reader or a workflow dashboard can name each profile, credit it, and tell that it is reference material rather than work in flight.

## What's New?

- **A `title` on every profile**, taken from its H1 (`Beads — Profile`, `Mem0 — Profile`, …). The existing `name:` key stays as it was.
- **`date_modified`** on every profile, from the file's last commit before this sweep (2026-08-18).
- **`authors`** on every profile, from its only human committer.
- **`status: Reference`** on every profile. Each one describes an upstream memory layer as it was studied at its pin, which is what `Reference` means: an agent consults it rather than follows it. None is a placeholder, and none says its pin is outdated.

## Under the Hood

- Part of the tree-wide OKF sweep; see the Context Vigilance Kit's plan, [[Retrofit-Every-Repo-to-OKF-Then-the-Kit-Frontmatter]], and the status vocabulary in the context-vigilance skill's `status-discipline.md`.
- Every edit was made by hand, frontmatter only. No body line changed, no existing date moved, and today's date was written into no existing doc.
- The profiles already had `site_uuid`, `hex_code`, and `date_created`, and carry no `tags`, so nothing needed minting or normalizing.
